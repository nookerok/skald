# Первый пятнадцатиминутный цикл

Статус: `OPEN` — это контракт и форма сбора доказательств, а не заявление о
пройденном human gate.

Skald должен за первые пятнадцать минут показать причинный цикл:

```text
намерение игрока → понятное последствие → новое наблюдение
→ естественно возникший вопрос → следующее намерение
```

## Golden world

Контракт сценария и граница доказательств описаны в
[`golden-world.json`](golden-world.json). Авторизованный browser smoke может
проверить оболочку, composer, player-space tabs, reload и отсутствие raw
идентификаторов. Он не доказывает удовольствие от игры и не заменяет
наблюдение за игроком; milestones в golden-файле намеренно требуют human
evidence и не выдаются за автоматическое покрытие причинного цикла.

Для локального технического прогона: `SKALD_PORT=3010 npm run start:server`, затем в другом shell:

`SKALD_BROWSER_BASE_URL=http://127.0.0.1:3010 npm run browser:smoke -- --world-url 'http://127.0.0.1:3010/#/world/<seeded-world-id>' --lease-file path/to/lease.json`

Для проверки игрового shell нужен заранее подготовленный мир. Lease-файл —
явный test-only fixture для свежего Playwright context:

```json
{
  "schemaVersion": 1,
  "worldId": "seeded-world-id",
  "acknowledgedWorldTime": 0,
  "acknowledgedEventNumber": 0
}
```

Smoke только устанавливает эту browser-session lease локально и не вызывает
endpoint подтверждения присутствия, не создаёт мир и не отправляет команду.
Без `--world-url` menu-проверка возвращает `BLOCKED`, потому что release UI
contract не был проверен.

Исходный длинный путь Riverwatch находится в
`packages/cli/acceptance-scenarios/riverwatch-old-course.json`; этот документ
выделяет из него первый игровой отрезок как отдельный продуктовый gate.

## Сценарий модератора

1. Дать игроку только стартовую сцену и попросить действовать своими словами.
2. Не подсказывать допустимые команды и не предлагать варианты действий.
3. Остановить запись на 5-й, 10-й и 15-й минуте и отметить последнее
   событие, наблюдение и вопрос игрока.
4. Спросить: «Что, по-твоему, изменилось?», «Что осталось неизвестным?» и
   «Что ты хочешь проверить дальше?».

## Acceptance scorecard

| Gate | PASS condition | Evidence |
| --- | --- | --- |
| First consequence | Игрок получает осмысленный результат примерно за 5 минут | timestamp + дословное описание игрока |
| Observation | Игрок замечает изменение или ограничение мира без подсказки | ответ игрока + turn id в test report |
| Agency | Есть минимум одно решение, сформулированное игроком, а не выбранное UI | transcript excerpt |
| Curiosity | К 15-й минуте игрок формулирует следующий вопрос | ответ игрока |
| Readability | Игрок может пересказать, что произошло, без raw ID и терминов реализации | moderator note |

Human gate остаётся `BLOCKED` до 5–8 независимых сессий длительностью
30–60 минут. `npm run validate`, acceptance scenario и browser smoke могут
подтвердить технические свойства, но не могут закрыть этот experiential gate.
